Our Journey: Crafting the Well-being Explorer

This is the story behind the OECD Well-being data visualization. Discover the steps we took, the hurdles we overcame, and the teamwork that brought it to life.

Path to the Final Product

Milestone 1: Foundations & Dataset Selection

The project kicked off with organizing weekly Zoom meetings. In our first meeting, each member proposed three datasets. After a shortlisting process and a vote, the OECD Better Life Index dataset was chosen.

A GitHub repository was established, and tasks for the Milestone 1 report were distributed:

  • Dataset Section: Francesco
  • Problematic Section: All members
  • Exploratory Data Analysis (EDA): Corvin (including data cleaning and histogram generation)
  • Related Work Section: Nicholas

Milestone 1 was completed by March 13, 2025, about a week ahead of the deadline.

Milestone 2: Prototyping and Initial Build

We began by defining the Minimum Viable Product (MVP) for our visualization. Key features included a 2D world map, interaction for year and OECD metrics (initially sliders, later a dropdown), a color scale for scores, handling for countries with no data, tooltips, and detailed views on click. We also brainstormed extra ideas like a 3D map and animations.

While the initial plan was to complete the report sections first, Francesco proactively developed and committed a website skeleton which already incorporated many core features: the 2D map, hover information, metric-time line graph, radar chart, and a time slider. This early prototype distinctively used a single dropdown for metrics instead of multiple sliders to differentiate from the official OECD site.

This accelerated progress led to a revised plan:

  • Dataset Preprocessing & Backend Integration: Corvin (including metric normalization)
  • Milestone 2 Report: Nicholas

Corvin also implemented an initial version of the color scale, though some CSS bugs remained.

Milestone 3: Refinement, Features, and Finalization

Francesco started Milestone 3 by refactoring code, fixing bugs, and adding dark mode, a color-blind scale, and a play button for the year slider.

Team discussions focused on improvements such as accessibility (advised by Nicholas), UI tweaks, and addressing a dataset naming bug. The OpenDyslexic font idea was dropped after user feedback. Milestone 2 feedback emphasized storytelling, leading to the decision to add a landing page and drop the 3D globe idea.

Due to competing deadlines, members worked more independently but fulfilled initial commitments. Key developments included:

  • Francesco: Added country comparison, the landing page, animations, fixed several bugs, and implemented the top/bottom 5 countries feature.
  • Corvin: Rewrote the dropdown menu for SVG icon compatibility and fixed the dataset naming bug.
  • Nicholas: Authored the process book, addressed accessibility violations on the landing page, and made final tweaks.

A TA meeting confirmed our direction and highlighted the need for the extrema feature. While major accessibility hotfixes for the landing page were implemented by Nicholas, some visualization page fixes and broader accessibility goals were deprioritized due to time constraints and grading scope. After final bug fixes and feature additions, the site was deemed complete, and the team proceeded to create the screencast.

Challenges Faced & Key Design Decisions

CSS Management and Scalability

A persistent challenge was managing CSS as the codebase grew. Styles became complex and interdependent, making changes difficult without unintended side effects. Existing CSS bugs also slowed development. This highlighted the need for a more structured CSS approach in future projects.

Dataset Naming Discrepancies

An undetected naming convention issue (e.g., "Czechia" vs. "The Czech Republic") caused some countries not to appear on the map. Corvin identified this during a meeting, leading to a dataset review and correction.

Scope Management: The 3D Globe

The initial idea for a 3D globe was ambitious. By Milestone 2, it was clear this would be complex and time-consuming. By Milestone 3, considering deadlines and feedback emphasizing narrative, the 3D globe was officially dropped to focus on core functionality and storytelling.

Web Accessibility (WCAG) Compliance

Achieving full WCAG 2.2 compliance was challenging due to time constraints and the guidelines' breadth. Core technical functionality was prioritized. Nicholas advised on accessibility, identified violations, and implemented feasible hotfixes, primarily on the landing page. Limitations remained, particularly for the visualization page regarding mobile optimization and advanced accessibility testing.

Sketches & Evolution

Initial Concepts and Development

Our initial sketches, primarily developed during Milestone 2, provided a strong visual guide for the main visualization page. We found that this early planning was quite robust, and the core layout and functionality of the final product closely matched these original concepts.

Sketch from Milestone 2 showing the planned map, controls, and display areas.

The primary evolution from these sketches occurred more in the technical implementation, data handling, and the addition of new features like the landing page, rather than drastic changes to the fundamental design of the visualization interface itself. One notable design change from the very early ideas was the decision to use a single dropdown menu for metric selection instead of multiple individual sliders, a choice made to enhance usability and differentiate our project.

The sketches effectively captured the intended user interaction flow, including the map, time slider, and areas for displaying detailed country information and charts.
